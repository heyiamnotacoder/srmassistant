# SRM Assistant — Agent Instructions

Harness for title/abstract screening and structured data extraction from research papers for systematic reviews and meta-analyses (SRMA). Works with any capable LLM agent — the workflow logic lives in plain-markdown prompts, not in any vendor's config format. All scripts are Python 3 stdlib only.

**Stage 0 — Protocol development** (research question → registrable protocol): follow `prompts/protocol-builder.md`. Sharpens the question, forces every eligibility and methods decision through a checklist, runs a scoping search for feasibility, and emits `protocol/pico.json`, `protocol/prospero_draft.md` (paste-ready, generated against `prompts/reference/prospero-fields.md`), `protocol/search/` (the line-numbered strategy per database plus its per-line counts, via `scripts/run_pubmed_strategy.py`) and `screening/criteria.json`. Skip only if the human already has a registered protocol.

**Stage 1 — Screening** (database exports → include/maybe/exclude): follow `prompts/screening-orchestrator.md`. Human drops `.ris`/`.nbib` files in `screening/exports/`; `scripts/parse_citations.py` parses/dedupes/batches; every batch is screened twice independently per `prompts/screener.md` (dual-pass); `scripts/merge_screening.py` adjudicates and emits PRISMA-ready results + a Rayyan-compatible `.ris` of survivors.

**Stage 2 — Extraction** (PDFs → data sheet): follow `prompts/orchestrator.md` (protocol → user-confirmed JSON schema → one extraction per PDF per `prompts/extractor.md` → `scripts/merge_extractions.py`). Outcome fields trace to protocol-registered outcomes, never to what the PDFs happen to report.

Both stages offer three execution modes — pick what your harness supports: parallel (subagents), sequential (single agent, fresh context per unit of work), or manual (human-driven chat UI).

## Layout

| Path | Purpose |
|---|---|
| `prompts/` | Canonical, tool-agnostic workflow + worker prompts (source of truth) |
| `prompts/reference/` | Verified external-format references (e.g. the PROSPERO field set), with provenance dates |
| `protocol/` | Generated by Stage 0 (`pico.json`, `prospero_draft.md`, `registration.json`, `amendments/`); also where the human drops an existing PROSPERO record or an extraction sheet template (CSV/XLSX) |
| `protocol/search/` | The search strategy and its results — line-numbered `strategy_<db>.txt`, per-line `<db>_counts.csv`, `search_log.md` |
| `screening/exports/` | Human drops database search exports (`.ris`, `.nbib`) |
| `screening/` | Generated: criteria.json, records, batches, decisions, results, `included_maybe.ris` |
| `papers/` | PDFs for the current review batch (screening survivors) |
| `schema/extraction_schema.json` | Generated schema — must be human-confirmed before extraction |
| `extractions/` | Per-paper JSON written by extractors (`<pdf-stem>.json`) |
| `output/` | Merged `extraction_sheet.csv`, `confidence_report.csv`, `missing_data_report.md` |
| `scripts/` | `run_pubmed_strategy.py`, `export_search_csv.py`, `make_search_docx.py`, `parse_citations.py`, `merge_screening.py`, `merge_extractions.py` (stdlib only) |
| `.claude/` | Claude Code adapters only (skills + project agents); other tools ignore this |

## Conventions

- One review at a time; archive or clear `protocol/`, `screening/`, `papers/`, `schema/`, `extractions/`, `output/` before a new review.
- The search strategy is part of the registered protocol, not a scratch note: every string that was actually run is kept in `protocol/search/` with the database, platform, date run and per-line yield, so PRISMA items 6–7 are transcribed rather than reconstructed. Changing a run strategy after registration is an amendment.
- The protocol is upstream of everything. Criteria and outcomes are derived from it once, confirmed once, and then not renegotiated — a genuine change is a protocol amendment recorded in `protocol/amendments/`, never a silent edit.
- Never tune eligibility criteria to change which studies survive, and never build outcome fields from what the papers report. Both are recognised biases (criteria-fitting, selective outcome reporting), and both are what registration exists to prevent.
- Screening verdicts err toward inclusion: ambiguity → `maybe`, never `exclude`; every exclude carries a PRISMA reason code; dual-pass disagreements demote to `maybe`. Screeners judge title/abstract only — no full-text or web lookups.
- Missing values: `NR` (not reported) vs `NA` (not applicable) — never blank, never guessed.
- Every field gets a confidence score (0–1); papers with overall confidence < 0.70 require human verification.
- Extractors never write to shared files — one JSON per paper; the merge script is the only thing that aggregates.
- To re-run one paper: delete its `extractions/<pdf-stem>.json` and re-run the workflow (already-extracted papers are skipped).
